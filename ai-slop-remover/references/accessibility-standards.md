# Accessibility Standards & WCAG 2.2 AA Compliance

When refactoring a website away from AI slop, visual improvements must never compromise technical accessibility. AI-generated code notoriously fails basic accessibility standards: low-contrast text, missing focus indicators (`focus:outline-none` with no replacement), `div` soup without ARIA roles, and unlabelled icon buttons.

This guide provides an actionable WCAG 2.2 Level AA compliance blueprint.

---

## 1. The Core WCAG 2.2 AA Checkpoints for Redesigns

### A. Color & Luminance Contrast (SC 1.4.3 & SC 1.4.11)
- **Normal Body Text**: Minimum **4.5:1** contrast ratio against the background canvas.
- **Large Text ($\ge 24\text{px}$ or $\ge 18.66\text{px}$ bold)**: Minimum **3.0:1** contrast ratio.
- **Non-Text UI Elements**: Minimum **3.0:1** contrast ratio for input borders, checkboxes, radio toggles, and graphical icons necessary for understanding.
- **Focus Indicators**: Minimum **3.0:1** contrast ratio against both the focused element and adjacent background colors.

### B. Focus Appearance & Navigation (SC 2.4.7 & SC 2.4.13)
AI templates frequently strip focus outlines to achieve a clean aesthetic:
```css
/* ANTI-PATTERN: Completely destroys keyboard accessibility */
button:focus, a:focus, input:focus {
  outline: none; /* NEVER DO THIS ALONE */
}
```
**The Compliant Solution**: Use `:focus-visible` with high-contrast dual-ring indicators:
```css
/* COMPLIANT: Visible, elegant, high-contrast focus indicator */
:focus-visible {
  outline: 2px solid var(--color-brand-accent);
  outline-offset: 2px;
}
```

### C. Touch Target Size (WCAG 2.2 SC 2.5.8)
- Every interactive button, link, icon trigger, or dropdown item must have an active target area of at least **$24 \times 24\text{px}$** (Level AA), with a strong recommendation of **$48 \times 48\text{px}$** for primary mobile controls.
- Provide at least 8px spacing between adjacent interactive elements to prevent accidental taps.

### D. Meaningful Semantic HTML Hierarchy (SC 1.3.1)
- **One and Only One `<h1>`**: Every route must have exactly one logical `<h1>` representing the main page topic.
- **No Skipped Heading Levels**: Do not jump from `<h1>` directly to `<h4>` simply to achieve a desired font size. Style an `<h2>` with appropriate visual classes instead.
- **Landmark Regions**: Ensure layouts utilize `<header>`, `<nav>`, `<main>`, `<aside>`, and `<footer>` instead of nested generic `<div>` containers.

## 2. Accessible Form Controls & Error Feedback

Forms generated by AI often omit `<label>` tags, relying entirely on `placeholder="Enter value"`. Placeholders vanish on typing, have notoriously low contrast, and fail screen-reader audits.

### Production-Ready Accessible Form Pattern:
```html
<div class="field-group">
  <label for="candidate-roll" class="block text-xs font-mono uppercase text-brand-text font-bold mb-1.5">
    Roll Number / Registration ID <span class="text-red-600" aria-hidden="true">*</span>
  </label>
  <input 
    type="text" 
    id="candidate-roll" 
    name="candidateRoll"
    required
    aria-required="true"
    aria-invalid="false"
    aria-describedby="roll-hint"
    class="w-full px-3.5 py-2.5 rounded-md text-sm border border-brand-border bg-brand-surface text-brand-text focus-visible:ring-2 focus-visible:ring-brand-accent focus-visible:outline-none"
  />
  <span id="roll-hint" class="block mt-1 text-xs text-brand-muted font-mono">
    Format: 10-digit number printed on your official admit card.
  </span>
</div>
```

## 3. Screen-Reader Accommodations & ARIA Discipline

### Rule 1: The First Rule of ARIA
*Do not use ARIA if a native semantic HTML element exists that does the job.*
- Use `<button>` instead of `<div onClick={...}>`.
- Use `<a href="...">` instead of `<span onClick={navigate}>`.
- Use `<dialog>` instead of a custom `div` overlay where possible.

### Rule 2: Unlabelled Icon Buttons
Every icon-only button (search icons, theme toggles, close buttons) must have an accessible label:
```tsx
// BAD: Screen reader announces "button" with no context
<button onClick={toggleTheme}><Moon className="w-5 h-5" /></button>

// GOOD: Explicit accessible text
<button 
  onClick={toggleTheme} 
  aria-label="Switch between light and dark visual themes"
  className="p-2 rounded-md hover:bg-brand-surface-2 focus-visible:ring-2 focus-visible:ring-brand-accent"
>
  <Moon className="w-5 h-5" aria-hidden="true" />
  <span className="sr-only">Toggle dark mode</span>
</button>
```

## 4. Respecting User Motion Preferences (`prefers-reduced-motion`)

AI slop often bombards users with infinite background gradient shifts, floating blobs, and continuous keyframe spins that can trigger vestibular disorders.

### Global CSS Reduced Motion Reset:
```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

In Tailwind:
```html
<div class="transition-transform duration-200 motion-reduce:transition-none">
  <!-- Content -->
</div>
```
